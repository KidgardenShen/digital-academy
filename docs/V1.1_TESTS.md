# v1.1 验收与复测

## 解压即可执行的校验

使用 Node.js 24，在 ZIP 解压根目录运行。随包的离线命令行已包含 Ajv、格式检查、Schema 和共享语义校验逻辑。

```sh
node portable/validate.mjs standards/fixtures/edition.json
node portable/validate.mjs --for-delivery standards/fixtures/ai-chapters.json
```

两条命令应返回 0，并分别显示结构版本 1.0.0、1.1.0。输出末尾另列注本数据修订号。普通校验验证文件是否可导入，交付校验额外检查今译覆盖和状态。将新示例首章的 `source_units[0].source_text` 改动一个字并另存，再次校验应返回 1，并指向该原文快照。ZIP 内 `MANIFEST.sha256` 按相对路径列出除清单自身以外每个文件的 SHA-256。

## 从源码复测

跨仓库验收使用 jingzhu-duidu 中的同一套合成输入。将含 1.1.0 修改的标准库检出至 `standards/jingzhu-duidu/`，或用环境变量 `JINGZHU_STANDARD` 指向其根目录。用 Python 3 安装上游 `requirements.txt` 后执行 `pnpm test:parity`（可用 `PYTHON` 指定解释器）。该命令先检查网站 Schema 和两份样例与上游一致，再分别用两个实际命令行核对普通与交付的预期退出码。仅运行上游检查可在标准库执行 `python tests/test_translations.py`。日常网站构建继续使用本地兼容副本。

```sh
pnpm install --frozen-lockfile
node scripts/validate.mjs standards/fixtures/edition.json
node scripts/validate.mjs --for-delivery standards/fixtures/ai-chapters.json
pnpm build
node scripts/build-validator.mjs
```

构建包含完整回归测试，最后一条命令用同一份源码在 `dist/portable/` 重新生成离线校验器和第三方许可证。也可以运行 `pnpm dev`，在本机新书架中导入示例，依次打开「问学」「践履」查看各章 AI 今译和复核状态。
