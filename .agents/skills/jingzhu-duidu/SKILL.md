# 经注对读 · 编辑工作流程 v1.1

## 确定这次整理什么

从项目根目录读取 [DATA_CONTRACT](../../../standards/DATA_CONTRACT.md) 和[标注规则](../../../standards/ANNOTATION_RULES.md)。字段和导入条件由契约与 Schema 维护。选择与委托匹配的 [任务配置](../../../task-configs/)，或复制其中的 `template.json`。记录原典底本、注疏底本、版本、责任者、全书或节选的范围，以及本次特有的章法。具体书目规则只适用于所选任务。先核实书影、卷页或可靠转录的出处，区分亲见与转引。缺材料时标明缺项及可交付范围。

## 整理原典与注疏

1. 依底本转录经文、序跋和注疏，保留原有层次、字形、标点与段落。将编者补题、存疑和异文说明单列。每个注疏版本独立成件。
2. 按文献体例判断实际解释对象。章句、集注中的字释可落到字词；注疏体系中的疏可直接解释注文；集解须分辨被引注家；讲义、训义中的通章论说可关联全章；译注材料须区分所附译文、校记和注解。篇、卷、经、章等层级跟随底本。
3. 先建立直接解释关系，再选读者点击原文的位置。整句释与附属字词释共用入口时，各留一条注文，显式安排弹窗次序。跨句注文只转录一次。逐一核对 UTF-16 半开区间、引文及重见处的出现次序和近邻文字。缺乏证据的对应关系列入待核清单。
4. 双向检查。由注疏回查经文和前注，核对解释对象、署名及出处；再从经文检查漏挂、重挂和章节入口。对照任务配置核对全书或节选的起讫、序文和章末材料。

## 逐章编写 AI 今译

根据本版该章所收的全部经文，按段写成连贯白话，使读者容易把握句意和上下文。可参校本版注文，遇有分歧时保留原文可容许的意思，避免把推论写成经文。逐段回读，核对否定、指代、承接和遗漏。材料所附现成译文保留原署名及出处。

将本轮 AI 译文写入契约的独立章节层，绑定本章原文及其快照，记录实际生成服务、已知模型、生成状态和真实人工复核情况。详见[双章示例](../../../standards/fixtures/ai-chapters.json)。修改译文或其依据后重新核对。模型自查只能记录为待人工复核。

## 验收与交付

使用[注本模板](../../../templates/edition.json)起稿。新制或重制注本逐章核对今译并运行 `node scripts/validate.mjs --for-delivery <文件路径>`。依错误路径修正，重新运行。交付独立 JSON、简要校核报告及尚待核实的事项。报告列出所用底本、范围、章数、注疏及今译覆盖、实际运行结果和人工复核状态；按事实标记草稿、已校或可入架。
